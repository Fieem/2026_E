# SCARA J1 关节控制器

该固件通过 FDCAN1 控制 SCARA 底座的无刷电机。主控不使用 IMU，也不运行
外部位置 PID；关节目标角度直接发送给 QD4310 的角度模式，由电机控制器
根据自身角度反馈完成位置闭环。

## 电机与 CAN 配置

- 电机节点 ID：`0x01`
- 控制指令 CAN ID：`0x401`
- 电机反馈 CAN ID：`0x501`
- CAN 模式：经典 CAN，速率 1 Mbit/s
- 反馈数据：QD4310 八字节状态帧

机械限位、旋转方向和零点偏移在 `App/scara_j1_config.h` 中配置。连接机械臂
之前，必须先校准这些参数。

系统复位后电机默认处于失能状态。J1 运行期间，如果 CAN 反馈或上位机心跳
超时，控制器将进入故障状态并立即使电机失能。

## 树莓派串口协议

USART1 波特率为 921600，数据帧采用小端字节序：

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 1 字节 | 固定为 `0xA5` |
| 负载长度 | 1 字节 | 该字段之后的数据字节数 |
| 命令 ID | 2 字节 | 见下方命令表 |
| 标志位 | 2 字节 | 保留字段，发送时填零 |
| 数据 | 0～8 个 float32 | 命令参数 |

| 命令 ID | 数据 | 功能 |
| --- | --- | --- |
| `0x0001` | 无 | 心跳 |
| `0x0101` | 无 | 以零转速使能 J1 |
| `0x0102` | 无 | 使 J1 失能 |
| `0x0103` | 角度，单位为弧度 | 设置 J1 目标位置 |
| `0x0104` | 转速，单位为 rpm | 手动转速模式 |
| `0x0105` | 无 | 停止并失能 |
| `0x0106` | 无 | CAN 反馈在线时清除故障 |

J1 处于运行状态时，树莓派应至少每 500 ms 发送一次心跳。当前上位机看门狗
超时时间为 1500 ms。

USART10 预留给第二块主控，用于控制两个步进电机、Z 轴舵机和电磁铁。
当前固件暂未处理 USART10 接收到的数据。

## 视觉通信接口

Gimbal1 通过 USART1 向树莓派发送识别开始帧，并接收树莓派返回的碎片位姿。
当前协议沿用 `0xA5 + 长度 + 命令 + flags + float32` 格式，不包含 CRC。

| 命令 ID | 方向 | 数据 |
| --- | --- | --- |
| `0x0201` | Gimbal1 → 树莓派 | START，flags 中为任务序号 |
| `0x0202` | 树莓派 → Gimbal1 | 每块碎片 6 个 float32 |
| `0x0203` | 树莓派 → Gimbal1 | 错误码 1 个 float32 |

`VISION_RESULT` 的 6 个浮点数依次为：

```text
拾取 J1、放置 J1、拾取 J2、放置 J2、拾取腕部角、放置腕部角
```

一块碎片对应一帧，2～4 块碎片对应 2～4 帧。Gimbal1 会检查任务序号、碎片
数量、碎片编号、角度有限性和 J1/J2 限位；收齐全部帧后状态才会变为 READY。
超时、缺帧、重复帧或错误码都会进入 ERROR，禁止继续执行动作。

上层动作任务在确认机械臂位于安全观测位置后调用：

```cpp
Vision_RequestStart();
```

该函数必须从 FreeRTOS 任务上下文调用，不能在中断回调中调用。视觉结果可通过
`Vision_GetResult()` 读取；当前工程只完成缓存和校验，J2 转发到 Gimbal2、
舵机和电磁铁动作留待下一阶段。

## 编译与烧录

```powershell
cmake --fresh --preset Debug
cmake --build --preset Debug
cmake --build --preset Debug --target flash
```

编译完成后，会在 `build/Debug` 目录中生成 `Gimbal1.elf`、`Gimbal1.hex` 和
`Gimbal1.bin`。执行烧录目标时，需要通过 SWD 接口连接 ST-LINK。
